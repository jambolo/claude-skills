# CLAUDE.md — `skill-management` family

Guidance for the `skill-version-check` and `script-version-check` skills. See the repo root `CLAUDE.md` for skill anatomy and repo-wide conventions.

## skill-version-check

`skill-version-check` keeps the installed skills under `~/.claude/skills/` and agents under `~/.claude/agents/` in step with this repo. It first refreshes the local clone from upstream `jambolo/claude-skills` (`git pull --ff-only` only — it never rebases, stashes, or discards; a blocked or unreachable pull is reported and the comparison continues against the local snapshot), then compares `manifest.json` against the installed versions, and optionally copies repo → install roots (a skill leaf is mirrored as a folder; an agent leaf's `AGENT.md` is copied as the single file `<name>.md` — never mirror the agents folder, it holds agents the repo does not own). Skills and agents are peers: every manifest entry declares `"kind"` as either `"skill"` or `"agent"`, neither is a default, and an entry with a missing or unrecognized `kind` aborts the comparison. An installed orphan whose name matches a manifest entry of the other kind is reported as `superseded` — a leftover of a skill → agent conversion that still dispatches — and may be removed with the user's confirmation. It never copies install root → repo, and it never touches plugin skills under `~/.claude/plugins/`.

## script-version-check

`script-version-check` is the same idea pointed at repos of standalone bash scripts (e.g. `jambolo/git-helpers`) instead of this repo. The target repo is whatever folder holds `manifest.json` (found by walking up from the cwd — there is no hardcoded upstream; Refresh pulls `--ff-only` from the repo's own `origin`, whatever it is, and never adds or rewrites a remote). Every manifest entry has `"kind": "script"` — the only kind; anything else aborts. A script's version lives in a `# version: x.y.z` comment within the first 15 lines (by convention directly under the shebang), since bash has no frontmatter. Sync copies single files repo → `~/bin/<name>` (`install -m 0755`); `~/bin` is not owned by the repo, so the skill never enumerates, mirrors, or deletes there and there is no orphan section. Never copies `~/bin` → repo.

## Two script ports per skill, kept in sync

Each skill's comparison logic exists twice. For `skill-version-check`: `scripts/Compare-SkillVersions.ps1` (`-RepoRoot`, `-SkillInstallRoot`, `-AgentInstallRoot`, `-Json`) and `scripts/compare-skill-versions.sh` (`--repo-root`, `--skill-install-root`, `--agent-install-root`, `--json`). For `script-version-check`: `scripts/Compare-ScriptVersions.ps1` (`-RepoRoot`, `-InstallRoot`, `-Json`) and `scripts/compare-script-versions.sh` (`--repo-root`, `--install-root`, `--json`). Each pair are ports of each other: same six statuses, same `Name` and `Kind` columns, same drift section (and, for `skill-version-check`, the same orphan section including the `superseded` marker), same `Summary:` line. **An edit to one must be mirrored in the other.** The bash ports deliberately work without `jq` (built-in manifest scanner as fallback) and without gawk-only features, so keep them that way. `*.sh` files are pinned to LF via `.gitattributes` so a Windows checkout cannot ship CRLF into a shebang.
